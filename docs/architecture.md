# 项目架构说明（持续更新）

> 本文档记录当前真实实现，不代替项目根目录的 `plan.md`。教师答辩话术统一在 P3 整理。

## 分层

- `app/controllers`：HTTP 入口、鉴权、参数校验和事务边界。
- `app/services`：面试追问、RAG、评分、语音识别和表达指标等业务逻辑。
- `app/models`：SQLAlchemy 数据模型与最小数据访问方法。
- `app/templates` + `app/static`：Flask 渲染的页面骨架、CSS 和原生 JavaScript 交互。
- `tests`：接口、事务、数据完整性和确定性算法的自动化验证。

## P1-A 语音链路

1. 浏览器用 `MediaRecorder` 录音，将浏览器音频解码并重采样为 16 kHz、16 bit、单声道 WAV。
2. `POST /api/interview/transcribe` 只校验、识别和分析，不写入面试消息，不推进题目。
3. 后端返回转写文本和与音频 SHA-256 绑定的限时签名回执。用户可回放、重录、取消或编辑转写。
4. 确认后调用 `POST /api/interview/<session_id>/reply`。回执验签成功时不重复请求讯飞；回执失效时安全回退为再次 ASR。
5. `InterviewMessage.raw_transcript` 保留原始转写，`content` 保留用户确认文本；`ExpressionMetric` 分开保存文本指标和声学指标。
6. 用户消息、表达指标、助手追问和会话进度使用同一数据库事务提交。

### 声学指标边界

`wav-rms-v1` 用 20 ms 短时帧计算有声时长、静音占比、300 ms 以上停顿、RMS 音量、音量波动、削波比例和信噪比代理值。它们是可由 WAV 重算的信号统计，不是情绪、人格、发音准确度或自信度结论。

本项目目前没有带人工标注的校准样本，因此不启用「自信度/情绪得分」，也不将声学统计混入技术综合分。

## P1-B RAG 链路

1. 追问、逐题评分和训练建议把岗位、题目、回答与标签交给 `retrieval_service`。
2. 检索先限定同岗位候选，再组合可解释规则分、SQLite FTS5/BM25 排名和可选的 Embedding 余弦相似度。
3. 结果必须超过相关度阈值；无关查询返回空列表，不用“最像的三条”冒充相关知识。
4. Embedding 由 OpenAI 兼容接口生成，当前实测配置为硅基流动 `BAAI/bge-m3`。知识向量连同内容哈希和模型名缓存；内容或模型变化时视为失效。
5. Embedding 未配置、超时或失败时触发 60 秒熔断，自动回退到 FTS5/规则检索，文字面试主流程不被外部服务阻断。
6. 每次业务检索写入 `retrieval_event`，保存使用场景、知识 ID、来源、相关度、检索方式和版本；逐题评分另存知识引用快照，因此删除知识条目不会破坏历史报告。

### 当前检索评测

固定评测集位于 `seed/retrieval_eval.json`，包含 16 条相关查询和 8 条无关查询。2026-09-22 在 405 条知识数据上的结果：

- FTS5/规则：Top-1 87.5%，Top-3 87.5%，无关拒绝率 100%。
- FTS5/规则 + `BAAI/bge-m3`：Top-1 93.75%，Top-3 100%，无关拒绝率 100%。

该数据说明 Embedding 对边缘表达有增益，但系统不依赖它才能运行。评测集规模仍小，不能替代真实用户查询和人工相关性标注。

## P1-C 题库与评分 v3

- 题目保存来源、审核状态、审核人、审核时间、内容版本和核心题标识。修改内容、参考答案、题型、标签或评分点时自动递增版本并退回待审核。
- 种子导入按统一规则把旧题映射到 1～5 级难度，并为每个岗位选出 30 道核心审核候选。抽题优先选择已审核核心题，同时维持题型和难度分布；审核未完成时兼容旧题库。
- Python 岗补充项目、场景和行为题，新增题都包含三个加权评分点，并明确标为 AI 辅助审核，不冒充人工结论。
- `mvp-v3` 将技术正确性、知识深度、逻辑结构、项目实践、岗位匹配和表达表现分开。每个维度保存状态、分数、证据、理由、建议和可信度。
- 技术分以评分点的渐进匹配为基础；只命中一个宽泛词不再获得整个评分点。回答长度只可辅助判断组织结构，不能直接制造技术高分。
- 纯技术题的项目实践标为“不适用”；没有语音指标时表达表现标为“待评估”。表达指标不参与技术综合分。
- LLM 输入统一放入 `untrusted_data`，系统提示明确禁止执行候选答案或知识块中的指令；输出需经过分数范围、评分点白名单和回答证据子串校验。

`seed/scoring_calibration.json` 当前展开为 36 个高、中、低样本。标签是开发期临时分档，不伪称人工评分；在获得盲评人工分之前不据此更改规则/模型融合权重。

## P2 训练、趋势与交付

1. 正式报告生成 3～5 个训练任务后，同时写入 `training_task`，任务状态从 `todo` 进入 `in_progress`，专项面试完成后变为 `completed`。
2. 专项训练仍复用面试状态机、逐题评分和报告服务，通过 `source_session_id` 与 `training_task_id` 追溯来源；放弃或删除未完成训练会把任务恢复为待训练。
3. 个人大屏只在同岗位、同 `scoring_version` 内计算正式面试的总分、题型和六维趋势，并展示高频/已改善薄弱点。
4. 专项训练与正式面试分开统计。复测差值只在评分版本一致时显示，并明确它是“完整面试 vs 三题专项”的训练参考，不冒充同卷实验。
5. 用户可导出自己的业务数据；删除账号需当前密码并由 SQLite 外键级联清理。密码哈希、Cookie 和外部服务凭据不进入导出。
6. Bootstrap 与 Chart.js 固化在 `app/static/vendor`，避免现场 CDN 故障；PowerShell 脚本负责首次安装、日常启动和发布包检查。

### 安全边界

浏览器写请求使用 SameSite Cookie 与 Origin 校验，登录失败按数据库/来源 IP/用户名限流，上传总量限制为 6 MB。API 异常统一输出 JSON，内部堆栈只写服务端日志且不记录请求体。当前限流存储在单进程内存中，适合本机 MVP；多实例生产部署需要 Redis 等共享存储。
